# Resource 修改约定

本文件只补充 `resource/` 的局部规则，继承根目录 `AGENTS.md`。表格中的短路径相对此目录，`src/`、`tools/` 和 `.codex/` 等路径相对仓库根目录。

## 快速定位

| 位置                                    | 职责                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------- |
| `tasks/tasks.json`                      | 主域任务图（作战、基建、公招、商城等）                                  |
| `tasks/<domain>/`                       | 按领域拆分的任务图（Stages、Roguelike、RA、MiniGame、UiTheme、Copilot） |
| `template/`                             | 模板匹配图片                                                            |
| `PaddleOCR/`、`PaddleCharOCR/`、`onnx/` | OCR 与识别模型                                                          |
| `global/<server>/resource/`             | 外服覆盖或补充                                                          |
| `platform_diff/`                        | 平台和窗口绑定模式差异                                                  |
| `roguelike/`、`custom_infrast/`         | 肉鸽策略与自定义基建配置                                                |
| 顶层 JSON                               | 招募、物品、战斗、基建、关卡等领域数据                                  |

从界面功能反查资源时使用 `../.codex/docs/feature-locator.md`；资源加载与 Core 边界见 `../.codex/docs/architecture.md`。

## 运行时契约

- `src/MaaCore/Config/ResourceLoader.*` 按主资源、缓存、服务器差异、服务器缓存、平台差异的顺序叠加；后加载内容可以补充或覆盖前层。
- `src/MaaCore/Config/TaskData.*` 合并文件并处理 `baseTask`、`@` 派生名、符号以及 `next`、`sub`、`onErrorNext` 等跳转。文件边界不等于运行时任务边界。
- 任务名、模板名、算法、动作、OCR 词条、JSON 字段和无动作能力标记都是跨 Core、WPF 与服务器资源的字符串契约。
- Core 可以根据最终合并后的能力标记选择兼容路径；不得仅按客户端名称在代码中复制同一能力判断。

## 修改原则

- 先查相邻任务、模板和服务器覆盖的既有模式，再做最小修改；保持字段顺序、命名、拆分和派生方式一致。
- 修改主资源时检查所有服务器和平台覆盖是否仍适用；修改覆盖时只表达差异，优先使用 `baseTask`，不要复制并冻结整份主配置。
- 新增、删除或覆盖能力标记时，检查各服务器最终合并结果、Core 参数校验和所有调用端行为。
- 重命名或删除任务、模板、OCR 词条和稳定 ID 前全仓搜索 C++、WPF、工具、文档及所有差异资源。
- 修改顶层数据或批量资源前，先搜索 `tools/ResourceUpdater/` 及其他生成器。属于生成输出时修改权威来源并重新生成，不直接维护派生文件；文件自身声明由外部工具生成时同样遵循其说明。
- 图片只提交识别所需的裁剪，保持相邻文件的尺寸、色彩、目录和命名约定，不顺手重压缩无关图片。
- JSON 和 YAML 交给 Prettier，不手工对齐，也不在功能修改中制造无语义的大面积排序或格式差异。

## 验证

- 对全部修改文件运行 `pre-commit run --files <paths>`，并复核格式化后的完整 diff。
- 至少确认 JSON 可解析、引用目标存在、模板和 OCR 资源可找到、任务链不会因缺失跳转目标而断裂。
- 涉及派生、符号、覆盖或能力标记时，检查各目标服务器的最终合并结果；必要时使用 Debug Core 的 `TaskData` 语法检查。
- 识别或流程变化需要对应客户端、分辨率和服务器的真实截图或日志证据，并记录未覆盖环境。
