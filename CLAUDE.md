## Read first

- `.codex/docs/` — start with `architecture.md` for document routing and repository layers; use `feature-locator.md` for UI/feature-to-code lookup, `wpf-core-bridge.md` for WPF runtime contracts, and `core-task-interface.md` for public Core tasks. ## Model-specific process

When the active model is Opus, enter plan mode before touching code: present the implementation plan and get explicit user approval first, and do not run edits, builds, or tests directly. This applies even to tasks that would otherwise skip planning under default criteria. Other models keep the default plan-mode judgment.

## Build (Debug x64)

`cmake` is not on `PATH` — it ships inside Visual Studio, and VS2026 installs under a directory named `18` (product year ≠ directory name). `ninja` sits alongside at `.../CMake/Ninja/`; `dotnet` is already on `PATH`.

```bash
export PATH="<vs-install>/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin:$PATH"
python3 tools/maadeps-download.py x64-windows   # once, or when the script changes
cmake --preset windows-x64
cmake --build --preset windows-x64-Debug --target MaaCore
dotnet build src/MaaWpfGui/MaaWpfGui.csproj -c Debug -p:Platform=x64
```

- `build/` is the single binary dir shared by all configs; `build/CMakeCache.txt` pins the generator, so re-configure after a VS upgrade.
- `build/bin/<Config>/resource` is a symlink to `resource/` — resource edits take effect without rebuilding.
- `windows-x64-clang` produces `compile_commands.json` for clangd only, not for building. Other presets: `linux-x64`, `macos-arm64`, `android-arm64`, `windows-publish-x64`, `smoke-test`.

## Test

Add or update focused regression tests when the change risk warrants them. Running any test still requires explicit user authorization. `unit_test/` (MaaCore pure algorithms, Catch2 + CTest) is a **standalone CMake project**, not part of the top-level build; suites register in **both** `unit_test/CMakeLists.txt` and `unit_test/test-suites.json` (the latter drives CI suite selection).

## Lint

`pre-commit run --files <paths>` — clang-format on `src/MaaCore/`, prettier on JSON/YAML under `resource/`, `src/`, `tools/`, markdownlint on docs. Prettier and markdownlint also cover the personal AI config docs (`.codex/docs/`, `.agents/*.md`, `.claude/*.md`, any `AGENTS.md`/`CLAUDE.md`) — run it after editing those too. "Files were modified by this hook" is auto-fix, not failure; re-run to confirm a clean pass. Always run it after editing `resource/*.json`.

## Gotchas that actually cause bugs

- Parts of `resource/` are generated by `tools/ResourceUpdater` from upstream game data — never hand-edit generated output. Target `res_updater`; output in `build/tools/ResourceUpdater/<Config>/`.
- Task node names in `resource/tasks/*.json` are a contract: C++ references them as strings, often via `std::format("XxxTask{}", index)`. Grep the C++ side before renaming or deleting one.
- `Config/TaskData.cpp` merges tasks base → base cache → server diff → server cache → platform diff. A shared-flow change can be masked by an override layer; derive overrides via `baseTask`, don't clone.
- Layer boundaries: `Vision/` extracts facts from screenshots (no device actions), `Controller/` does device I/O only, state machines live in domain tasks, and WPF reimplements neither.
- Changing `include/AsstCaller.h` fans out to WPF `MaaService`, every language binding under `src/`, and the protocol docs.
- Toolbox tasks append straight through `AsstProxy` and share `RunningState`. Task-queue features additionally need a persisted model, settings page, `ITaskQueueModelSerialize`, a Core interface task, callback routing, localization, and config migration.

## Live testing

Authorization is required **per instance** (see `AGENTS.md`). Runtime logs: `build/bin/<Config>/debug/gui.log` (WPF) and `asst.log` (Core). PowerShell scripts holding Chinese literals must be UTF-8 **with BOM**, or `Find-ByName` silently matches nothing.

## Git

Never hard-wrap commit message bodies to a fixed column width. Keep each logical paragraph or list item on one line, and add line breaks only at semantic boundaries.
