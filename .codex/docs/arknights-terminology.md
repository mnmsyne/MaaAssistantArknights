# 明日方舟术语与仓库字段对照

本文用于阅读 MAA 代码、资源、配置和回调时统一游戏术语。相同字段名在不同协议中可能具有不同含义，使用前仍需确认所属任务和数据模型。

## 日常任务与作战

| 字段、类型或模块         | 游戏 / 产品术语 | 含义                                                       |
| ------------------------ | --------------- | ---------------------------------------------------------- |
| `StartUp`                | 开始唤醒        | 启动客户端并进入可执行任务的状态                           |
| `Fight`                  | 刷理智 / 作战   | 进入关卡并按资源、次数或掉落目标重复作战                   |
| `Infrast`                | 基建换班        | 处理设施、干员排班、无人机等基建事务                       |
| `Recruit`                | 公开招募        | 识别标签、选择组合并处理招募位                             |
| `Mall`                   | 信用购物        | 领取信用并按配置购买物品                                   |
| `Award`                  | 领取奖励        | 领取日常可用奖励                                           |
| TaskQueue / Farming      | 一键长草        | WPF 持久化并顺序执行的一组日常任务，不是单一 Core 任务     |
| `stage`                  | 关卡            | 稳定的关卡编号或导航目标                                   |
| `times`                  | 作战次数        | 希望执行的总次数；具体终止仍受理智、掉落目标和任务结果影响 |
| `series`                 | 代理倍数        | 单轮连续代理选择；它与总作战次数不是同一概念               |
| `sanity` / `sanity_cost` | 理智 / 理智消耗 | 当前理智或一轮实际识别出的理智消耗                         |
| `medicine`               | 理智药          | 允许使用的理智药数量或策略                                 |
| `stone`                  | 源石恢复理智    | 是否或允许多少次使用源石恢复理智                           |
| `drops`                  | 掉落目标        | 物品 ID 到目标数量的映射，达到目标后可结束作战             |

“一键长草”属于客户端编排：WPF 将各任务设置序列化为多个 Core 请求，并用任务 ID 追踪状态。不要把它误解为 MaaCore 中名为 Farming 的接口任务。

## 仓库与物品

| 字段或模块           | 产品术语 | 含义                                         |
| -------------------- | -------- | -------------------------------------------- |
| `Depot`              | 仓库识别 | 识别物品 ID、名称和数量并返回结构化结果      |
| Depot result / cache | 仓库缓存 | WPF 保存的最近识别结果，供界面和其他功能复用 |
| `item_id`            | 物品 ID  | 跨语言和本地化稳定的物品标识                 |
| `item_index.json`    | 物品索引 | 物品名称、图标和用途等基础数据来源           |

仓库识别属于 Core 的可复用识别能力，也可由 WPF 小工具直接调用。展示名称可以本地化，任务参数和缓存关联应使用稳定物品 ID。

## 干员基础字段

| 仓库字段或类型                                     | 游戏术语      | 取值与注意事项                                |
| -------------------------------------------------- | ------------- | --------------------------------------------- |
| `id` / `operator_id`                               | 干员 ID       | 比本地化名称稳定，适合协议、配置和关联        |
| `name`、`name_en`、`name_jp`、`name_kr`、`name_tw` | 干员名称      | WPF 可按当前语言名称或别名查找                |
| `profession` / `OperatorRole`                      | 职业          | 表示八大职业，不表示分支                      |
| `subProfessionId`                                  | 分支 ID       | 原始数据中的稳定分支标识                      |
| `rarity`                                           | 稀有度 / 星级 | 普通干员通常为一至六星                        |
| `elite`                                            | 精英化阶段    | `0` 为未精英化，`1` 为精英一，`2` 为精英二    |
| `level`                                            | 干员等级      | 当前精英化阶段内的等级，需与 `elite` 一起解释 |
| `potential`                                        | 潜能          | 干员潜能等级                                  |
| `own`                                              | 已拥有        | 干员识别结果中的持有状态                      |
| `position`                                         | 部署位置类型  | 通常区分近战位、远程位或内部特殊类型          |
| `rangeId`                                          | 攻击范围 ID   | 指向战斗数据中的范围定义                      |

## 职业映射

| 数据值    | `OperatorRole` | 游戏术语 |
| --------- | -------------- | -------- |
| `WARRIOR` | `Warrior`      | 近卫     |
| `PIONEER` | `Pioneer`      | 先锋     |
| `MEDIC`   | `Medic`        | 医疗     |
| `TANK`    | `Tank`         | 重装     |
| `SNIPER`  | `Sniper`       | 狙击     |
| `CASTER`  | `Caster`       | 术师     |
| `SUPPORT` | `Support`      | 辅助     |
| `SPECIAL` | `Special`      | 特种     |

`Drone`、`Token` 和 `Trap` 是召唤物或装置的内部类别，不属于普通干员筛选中的八职业。

## 等级、技能与专精

| 字段或参数                             | 游戏术语        | 上下文                                       |
| -------------------------------------- | --------------- | -------------------------------------------- |
| `skill_level` 的 `1` 至 `7`            | 技能等级 1 至 7 | 干员基础技能等级，多个技能共享               |
| 战斗需求中的 `skill_level` `8` 至 `10` | 专精一至专精三  | 部分战斗配置用连续整数表达技能等级与专精     |
| 训练室任务中的专精等级 `1` 至 `3`      | 专精一至专精三  | 只记录专精阶段，不与基础技能等级合并         |
| `continue_training`                    | 继续专精        | 训练完成后尝试继续当前技能的下一阶段         |
| `skill_index`                          | 技能序号        | `1`、`2`、`3` 分别表示技能一、技能二、技能三 |

看到 `skill_level` 时必须先确认所属协议。作业显示和参数传递也应区分技能序号、基础技能等级和专精阶段。

## 基建概念

| 字段或模块            | 游戏术语    | 含义                                                             |
| --------------------- | ----------- | ---------------------------------------------------------------- |
| facility / room       | 设施 / 房间 | 控制中枢、贸易站、制造站、发电站、宿舍、会客室、办公室、训练室等 |
| plan                  | 基建方案    | 一组设施顺序、干员分配和换班策略                                 |
| dormitory             | 宿舍        | 恢复干员心情的设施                                               |
| mood                  | 心情        | 影响干员能否继续工作的状态                                       |
| drones                | 无人机      | 可加速贸易、制造等设施进度                                       |
| reception             | 会客室      | 线索收取、交流和信用相关操作                                     |
| training              | 训练室      | 对已满足条件的技能进行专精训练                                   |
| custom infrastructure | 自定义基建  | 按用户方案文件而非通用自动策略排班                               |

基建资源描述页面入口和可执行动作，领域任务负责换班顺序、心情与设施状态。界面显示名称不应替代资源或协议中的稳定设施类型。仓库字面标识为 `Control`、`Trade`、`Mfg`、`Dorm`、`Power`、`Reception`、`Office`、`Training`、`Processing`（见 `infrast.json`），阅读代码和资源时按这些键查找。

## 作业与识别

| 字段或模块         | 产品术语   | 含义                                            |
| ------------------ | ---------- | ----------------------------------------------- |
| `Copilot`          | 作业       | 读取作业配置并辅助编队和战斗                    |
| requirements       | 干员需求   | 作业对精英化、等级、技能和模组等条件的约束      |
| `OperBox`          | 干员识别   | 从干员列表识别持有、等级、精英化、潜能等事实    |
| `Recruit` tool     | 公招计算   | 识别标签并计算可选组合，通常从小工具页运行      |
| `SubTaskExtraInfo` | 子任务信息 | Core 向调用端报告稳定事件和结构化结果的通用载体 |

干员筛选只帮助用户定位或选择干员，不等同于扫描账号培养状态。WPF 可以提前提示作业需求，Core 仍需校验直接调用方发送的配置。

## 数据来源与边界

- `resource/battle_data.json` 提供干员 ID、本地化名称、职业、稀有度、部署位置、攻击范围和分支 ID 等战斗基础数据。
- WPF `DataHelper.Operators` 过滤非普通干员，并提供本地化名称和别名查找。
- `resource/item_index.json` 提供物品名称、图标索引和用途等基础信息。
- `OperBoxImageAnalyzer`、`DepotImageAnalyzer`、`RecruitImageAnalyzer` 等领域分析器从截图返回事实，不负责客户端页面编排。
- 游戏数值或关系未包含在仓库数据中时，不应仅凭界面显示名称或经验猜测生成协议字段。
